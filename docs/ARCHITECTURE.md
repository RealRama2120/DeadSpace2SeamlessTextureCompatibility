# Architecture and validation boundaries

The x86 `version.dll` forwards all 17 exported version APIs to Windows' system copy. In a host named `deadspace2.exe`, it installs an in-memory entry-point detour. The handoff runs after loader initialization rather than launching a process from DllMain. It never changes the executable on disk. MarkerPatch, dgVoodoo and ReShade continue to own their existing proxy filenames.

The companion scans packages, verifies streaming ZIP/TPF integrity and content identities, orders selected packages and holds read locks to prevent deployment races. An original trusted TexMod is reused, or explicitly consented to and downloaded over HTTPS with pinned archive and executable checksums. The companion selects the intended executable, submits the packages and reads TexMod's list back before invoking Run.

The TexMod child inherits a recursion guard and a unique runtime-evidence directory. The waiting Steam parent exits only after the companion ends. A disabled/no-pack result resumes the original parent entry. Missing companion files resume the original game; failures to start an existing companion are reported. The rendered child does not automatically inherit every Steam overlay behavior of the waiting parent; module presence is recorded separately.

The child observer hooks Direct3DCreate9, device creation, texture creation, level-zero locks/unlocks and texture binding. It hashes source uploads using the native TexMod CRC convention. At a selected target's first bindings, it queries the actual bound texture, checks that TexMod substituted a different object, and reads its pixels. Supported DDS DXT1/3/5 blocks are decoded into canonical BGRA pixels so equivalent compressed endpoint changes do not cause a false mismatch. Supported ARGB/XRGB images are compared in their native layout. Only the named, encountered target is then marked verified.

This observer is read-only with respect to texture data but changes in-process API dispatch and adds hashing/readback work. It is not a formal guarantee of every draw, mip level, scene or graphics stack. It does not verify cube/volume textures, arbitrary image formats, ambiguous internal archive entries, or formats converted to a different representation. Unreadable substitutions, unchanged bound objects and readable pixel mismatches are reported separately. Once a target is verified, later binds of that same hash are not continuously revalidated.
The observer distinguishes an unchanged bound object, an unreadable candidate, and a different bound object whose exact pixels mismatch. A pixel mismatch does not prove that no replacement occurred: TexMod or the graphics stack may transform an image. The runtime still requires an exact pixel match for `INJECTION_VERIFIED` and does not silently promote dimension changes to that result.
Inconclusive observer results are logged without modal warnings in the release candidate. Actionable package and launch failures still display an error. The companion drains the runtime log once more after the game exits before writing its summary.

MinHook is a vendored dependency. The companion's Win32 TexMod automation and acquisition code are adapted from Rama2120's Dead Space 2008 Seamless Texture Compatibility source. There is no installed DS1-mod dependency. The game-support Vortex extension, TexMod Autoloader, MarkerPatch and RTT audit were read-only references. Return to Titan content, TexMod, game binaries, dgVoodoo, ReShade, REST, Conduit files and user data are excluded from distribution.
